# Companion UI: implement these verbs first

1. **Handshake and roster:** `roster`, `list`, `help`, `features`. Accept the real `TBM:TRANSPORT|party` handshake before sending TBM addon messages on PARTY. Build the bot list and capability state from complete streams. Our temporary hires produce an empty `ROSTER` stream but populated `CC_ASSIGN` and `BOTSTATE` streams; do not silently invent persistent roster rows or protocol/version lines absent from the capture.
2. **Companion and party controls:** `invite`, `summon`, `action follow/stay`, `status`, `behavior`, `formation`, `role`. Scope changes to the selected owned bot. Treat ACK, ERR and stock text as separate valid outcomes. `release` is the spirit-release action, not dismissal; this server dismisses temporary hires with `remove` (supplemental cleanup capture).
3. **Bot panel:** `inv`, `item`, `command`. Preserve all equipment and carried-item rows, copper and capacity. Treat bag and slot as server coordinates: the live server uses bag 255 for equipment/backpack. Its successful unequip form takes **bag and slot**, whereas the supplied protocol documents only slot. Forwarded commands can reply in bot whispers as well as system/addon text.
4. **Basic upkeep:** `ready`, `rest`, `repair`, `sell`, `learn`, `downtime`, `autogear`, `maintenance`. A valid request may report zero affected bots, no vendor or a permissions refusal. Do not show success merely because the RPC call succeeded. The documented `rebuff` verb is rejected on this deployed Turtle build.
5. **Class services and professions:** `service`, `totem`, `professions`; gate `choice` and `blessing` on support. Keep recipe streams intact. This deployed build rejects `choice` and `blessing`; these files are negative compatibility fixtures, not successful implementations.
6. **Later features:** `lootlog`, `alts`, `order`, `run`, `commander`, `cmd`. Guild orders require guild context; the test controllers are not guild members, so order captures demonstrate real permission errors, not populated order streams. Run/commander controls must not be required for the basic companion panel.

Start with tolerant parsing and explicit errors. Preserve unknown capability tokens/extra fields without enabling nonexistent buttons. These fixtures describe one live Turtle build; the protocol document and Forever's intended implementation are separate contracts.
